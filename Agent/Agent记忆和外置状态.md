# Agent 记忆和外置状态

## 先分清记住了什么

对话历史保存了发生过的交流，但它不是所有事实的可靠数据库。用户可能改变决定，模型可能留下未验证的推测，业务状态也可能在对话之外变化。我理解的记忆，是有选择地保存后续仍有用的信息；外置状态则把任务进展存到独立于当前上下文的位置。

两者可以重叠，却有不同目的。任务状态关心哪一步已经完成、哪个产物可继续使用；偏好记忆关心用户通常希望怎样表达或操作；业务事实则应以相应系统为准。把这些内容混成一段摘要，容易让历史习惯覆盖当前要求，或者把曾经正确的事实当成永久事实。

## 任务状态应当清楚且可更新

我会用少量稳定字段记录任务目标、约束、已完成项、未解决项和产物引用。字段不必复杂，但要能区分未开始、执行中、已完成和失败。一个动作只有在得到适当确认后，才能从执行中变成已完成，否则恢复时会跳过实际未完成的工作。

并发任务还要避免互相覆盖状态。例如两个步骤同时修改同一份进度文件，后写入者可能抹掉前一个结果。可以使用版本号、受控更新或合并规则处理，而不是让各个模型任意改写整份状态。对于较简单的个人任务，单一写入者往往比复杂的协调机制更易维护。

## 长期记忆不是越多越好

适合长期保留的内容通常具有明确用途，例如稳定偏好或已经确认的项目约定。一次临时选择不必立刻升级成永久偏好。写入时可以记录适用范围、确认时间和更新依据，让后续系统知道这条信息是否仍应使用。

记忆也要有修正与删除入口。用户明确纠正一项信息时，不应只添加一条新记录，却让旧记录继续以相同权重被检索。删除需要考虑相关索引、摘要和缓存，不能只隐藏界面中的一行文字。不同用户或项目之间的记忆读取，还应遵守原有的数据隔离范围。

## 假设一个跨会话整理任务

假设我今天整理学习笔记，明天继续。任务状态可以保存已处理文件、待处理文件和分类规则；记忆可以保存我偏好简洁的中文说明。第二天开始时，系统读取当前文件清单与检查点，再询问或执行下一项工作，而不是把昨天所有工具原文重新塞入上下文。

如果今天我要求保留原文件，明天明确要求在副本上重写，系统应根据最新范围继续。若某篇文章已经被我手工修改，外置状态中“完成”的标记不代表可以覆盖它。恢复时需对照文件版本与当前内容，必要时重新合并。记忆提供线索，实际对象提供当前事实。

## 怎样观察记忆是否有用

我会设计连续任务检查：中断后是否能接上，用户改变偏好后是否跟随更新，插入无关话题后是否仍能找到关键限制，以及不同身份能否只读取自己的内容。还可以故意写入一条错误记忆，再执行纠正，观察旧说法是否持续影响回答。

评估时不只看系统记住了多少。错误信息被重复引用、过期事实没有更新、私有内容出现在错误任务中，都是记忆带来的代价。对短任务，显式状态加少量摘要可能已经足够；只有在跨会话需求明确时，再增加检索、失效和管理能力。把记忆做成可查看、可解释、可修正的资料，比让它显得无所不知更实用。
