# 让 Agent Loop 可结束、可检查

一个 Agent 能连续调用工具，只说明它能行动；是否完成任务，还需要外部条件判断。我目前用四个问题检查 Loop 的设计。

1. **可终止**：完成、超时、超预算、错误或转人工的条件是什么？
2. **可验证**：结果由谁检查？文件、接口状态或测试是否满足要求？
3. **可观测**：能否从运行 ID 找回每一步的输入、工具结果和状态？
4. **可恢复**：遇到暂时故障、参数错误或权限问题时分别怎么处理？

## 一个简化的运行契约

```text
输入：目标、允许的工具、步骤和时间上限
每一步：记录状态 → 执行动作 → 读取反馈 → 检查进展
结束：验证通过 / 上限触发 / 需人工处理 / 不可恢复错误
```

把“模型说完成了”当成完成条件很危险。比如生成报告，至少还要检查文件存在、格式符合要求、引用能打开；高影响的外部写入还要有人工控制点。

目前这是一份设计检查法。我还没有在真实生产 Agent 中完成故障注入与长期运行验证，所以具体预算和恢复策略必须跟场景一起定。
