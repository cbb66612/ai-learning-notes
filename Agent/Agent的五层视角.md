# Agent 的五层视角

我用五个问题理解一个 Agent，而不只看它能不能生成一段像样的回答。

| 层 | 我会问什么 |
| --- | --- |
| 目标 | 任务是什么？什么时候算完成或应该停下？ |
| 上下文 | 当前步骤真正需要哪些资料、历史和约束？ |
| 行动 | 可以调用什么工具？输入、权限和失败返回是什么？ |
| 运行支撑 | 状态存在哪里？预算、日志、人工控制点由谁负责？ |
| 循环 | 每一步如何根据环境反馈继续、修正或结束？ |

例如“帮我找一个合适的资源”：先定义“合适”的条件，检索时只提供相关目录和筛选规则；工具返回候选后还要打开内容确认，而不能从标题推断详情。若资源不存在，回答应该说明查找范围和缺口。

## 几个容易混淆的地方

- 模型一次调用、ReAct 循环和完整的 Agent 系统不是同一层概念。
- 长上下文可以装更多信息，却不能自动提供可靠状态、权限和验收。
- MCP 能统一工具连接方式，具体业务仍要定义权限与错误处理。
