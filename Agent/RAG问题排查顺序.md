# RAG 问题排查顺序

看到 RAG 回答不对时，我会先定位错误发生在哪一段，而不是立刻调 Prompt。

```text
资料接入 → 解析与分块 → 索引 → 查询与召回
       → 重排与上下文 → 生成 → 引用与事实检查
```

## 按症状找问题

| 症状 | 先看哪里 |
| --- | --- |
| 应该有的内容没找到 | 解析是否丢段、权限过滤、分块边界、查询表达、召回结果 |
| 找到了却答错 | 上下文排序、冲突内容、指令和生成忠实度 |
| 答案流畅但说不清出处 | 引用定位、原文对照和外部事实 |

分块大小、Top-K 和阈值都需要结合文档形态、成本与实际问题集调整，没有能直接照搬的数字。相似度高也只说明表示接近，不保证事实正确。

我还想把评测拆成三层：检索是否找到所需段落、上下文是否保留关键条件、最终回答是否忠实且能定位出处。这样比只给整条回答打分更容易找到原因。
