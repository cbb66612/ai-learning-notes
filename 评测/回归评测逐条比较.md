# 回归评测要逐条比较

改模型、Prompt、Skill 或工具后，我不会只看“通过了几条”。总数相同也可能有的改善、有的退步。

## 开始前

- 固定输入、资料、会话状态、工具版本和测试顺序；拿不到的版本信息明确写未知。
- 每个用例先写通过、部分通过、失败的判断标准。
- 保留首次回复，追问后修正单独记录。

## 对比时

| 本轮变化 | 应如何记录 |
| --- | --- |
| 改善 | 哪一步变好了，依据是什么 |
| 退步 | 新增问题及复现方法 |
| 持续问题 | 原问题是否仍在 |
| 未复测 | 不推断已修复 |
| 条件变化 | 只描述表现，不归因于某个模型 |

例如 10 条测试中两次都通过 5 条，仅看合计会以为没有变化；如果其中 1 条从失败变通过，另 1 条从通过变失败，后续工作就完全不同。

一次回归的结果先用于找问题。要得出稳定的模型优劣结论，还需要同条件、足够样本和重复测试。
