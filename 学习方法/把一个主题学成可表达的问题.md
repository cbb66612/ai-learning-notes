# 把一个主题学成可表达的问题

资料多的时候，我容易把“看过”误当成“会解释”。所以我给自己留一个短循环：

1. 先写一句当前结论，并说明它成立的条件。
2. 不看资料，讲清关键机制。
3. 找一个权衡或失败场景。
4. 写两个追问：一个问原理，一个问实际落地。
5. 回头核查回答不出的部分，再修改笔记。

比如“长上下文能否替代 RAG”，我会先说它们处理的是不同问题：前者扩大单次可读范围，后者在运行时选择材料并建立可追踪的引用。接着问资料更新、权限、成本和噪声如何处理，再决定具体场景适合哪种方案。

模板只帮助我发现思路的缺口。版本、性能数字和真实项目经历仍要从当前资料或实际运行中核对，不能因为表述顺畅就补成事实。
